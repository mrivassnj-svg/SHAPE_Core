1. Project Overview

SHAPE (Self-Healing Autonomous Programming Engine) is a multi-tier AI coding-agent system designed to assist developers and field technicians with code generation, static analysis, and environment-aware programming guidance — even when network connectivity is limited. The agent runs entirely on-device using an Ollama-hosted codellama:13b language model and a LangGraph ReAct reasoning loop, requiring no cloud subscription.

The system addresses three real-world pain points in embedded and DevOps workflows:

  1. Offline code generation — writing, debugging, and explaining code without access to cloud LLMs.
  2. Sensor-driven auto-action — automatically generating alert code and remediation scripts when physical sensors detect anomalous conditions.
  3. Continuous RL improvement — a lightweight reinforcement learning feedback loop that improves agent behavior over repeated interactions.

SHAPE maps to Option 2: Automation Agent from the project brief. The system decomposes user requests into tool-use sub-steps, executes them sequentially with error handling, and adapts when a step fails.

2.2 Agent Architecture (ReAct)

SHAPE implements the ReAct (Reasoning + Acting) pattern via LangGraph. The agent loop is:

  1. Input Processing — safety guard screens the prompt; metadata and RL policy hints are appended.
  2. Reasoning — CodeLlama plans the next action using chain-of-thought.
  3. Tool Dispatch — the agent selects one of four tools and receives a structured observation.
  4. Observation Integration — the observation is added to the sliding 10-turn memory window.
  5. Output Generation — when no further tools are needed, the final answer is returned.

3. Implementation Details

3.1 LLM Integration (Ollama + CodeLlama)

Rather than a cloud API, SHAPE uses Ollama running locally on the Raspberry Pi 5 to serve codellama:13b. The LangGraph agent communicates with the model via langchain_ollama.ChatOllama. A system prompt establishes SHAPE's persona and injects the current RL policy hint. A sliding-window message buffer (last 10 turns) keeps context compact enough for the Pi 5's 8 GB RAM.

llm = ChatOllama(
    model="codellama:13b",
    base_url="http://localhost:11434",
    temperature=0.2,
    num_ctx=8192,
)

3.2 Tool Integration

Four tools are registered as LangChain Tool objects and bound to the agent:

ToolWhen usedError handling
execute_python User asks to run, test, or verify code Subprocess timeout; stdout/stderr returned; no network access
lint_code User asks to find bugs or quality-check code Returns pyflakes messages or "No issues found"
file_manager Read, write, or list files in the workspace Path sandbox; writes outside workspace return an error string
doc_search User asks about Python APIs, library docs FAISS lookup with keyword fallback; returns "No results found" gracefully

3.3 Reinforcement Learning Feedback Loop

SHAPE implements a lightweight policy gradient analogue: user ratings (1–5 stars) are normalised to a 0–1 reward signal and fed into an exponential moving average. When the rolling average drops below a configurable improvement threshold, the system injects a corrective policy hint into the next system prompt, biasing the agent toward simpler, more-explained output. This satisfies the assignment's requirement for:

  • Feedback Mechanism — explicit 1–5 user rating per response.
  • Reward System — normalised score stored and averaged.
  • Policy Improvement — hint injected when rolling average < threshold.

3.4 Safety and Security

The InputGuard class in safety.py applies four layers of protection:

  1. Input validation — regex patterns block shell injection attempts, known exploit strings, and excessively long inputs (> 2 000 characters).
  2. Boundary enforcement — the system prompt explicitly restricts the agent to coding tasks; requests outside the domain return a polite refusal.
  3. Fallback strategies — Ollama unavailability is caught; the Zero 2 W serves cached responses; the Pico 2 continues displaying sensor data independently.
  4. Transparency — the agent prefixes uncertain answers with [SHAPE] and always states when it cannot fulfill a request.

3.5 Hardware Firmware (Pico 2 MicroPython)

The Tier-1 node runs pure MicroPython on the RP2350. Key design decisions:

  • A custom ST7789 SPI driver (st7789.py) was written from scratch because existing MicroPython ST7789 libraries do not include an embedded bitmap font.
  • The 5×7 ASCII bitmap font is stored as a 475-byte bytes literal — no filesystem access needed, fits in flash.
  • UART telemetry uses a simple SHAPE,{ts},{t},{h},{aqi},{alert} CSV protocol so the Zero 2 W can parse it without a JSON parser.
  • The Pico's main loop runs at a 10 ms tick; sensor reads fire every 2 s; LCD redraws every 250 ms — keeping CPU load well below 5 %.

4. Step-by-Step Agent Sequence

The following describes the exact sequence from user input to delivered result:

  1. User input arrives — via CLI (main.py), Zero 2 W LCD preset, or Pi 5 HTTP POST /query.
  2. InputGuard screening — safety.py rejects harmful patterns; safe inputs proceed.
  3. RL context injection — feedback.py appends a policy hint to the system prompt if the rolling average is below threshold.
  4. LangGraph ReAct loop starts — the graph node agent calls the LLM with the full message history.
  5. LLM reasons and selects a tool — CodeLlama emits a tool-call JSON object (e.g. {"name":"execute_python","arguments":{"code":"..."}}).
  6. Tool executes — the selected tool runs (sandboxed subprocess / FAISS lookup / pyflakes / file I/O) and returns a string observation.
  7. Observation fed back — the observation becomes a new ToolMessage appended to the message history.
  8. Steps 5–7 repeat until the LLM emits a plain text answer (no tool call).
  9. Answer returned — the final text is sent to the caller (stdout / HTTP JSON / Zero 2 W LCD screen).
  10. User rates the response — 1–5 stars entered via joystick or CLI; the RL reward loop updates the rolling average.
  11. Sensor auto-query path — if the Pico 2 reports AQI > 600 or temp > 40 °C, the Pi 5 /sensor endpoint automatically injects a remediation query into the agent (steps 3–9) and returns the alert text to the Zero 2 W and Pico 2 displays.

7. Lessons Learned

Cherluk Sumdin — Design Contribution

Designing the three-tier hardware architecture taught me how critical protocol choice is at the boundaries between subsystems. Switching from JSON to CSV at the UART layer reduced Pico 2 RAM usage by ~8 KB and eliminated parse errors under high sensor noise. Future projects should define wire protocols before writing any application code.

Olubukola Kukoyi — Coding Contribution

Implementing the RL reward loop showed me that "reinforcement learning" does not always require a full Markov Decision Process. A rolling exponential average with a policy hint is sufficient to demonstrate measurable improvement and is orders of magnitude simpler to debug on resource-constrained hardware.

Taki Eddine Boubekri — Coding Contribution

Building the MicroPython LCD driver from scratch deepened my understanding of SPI timing and the importance of pixel-buffer chunking. Writing 240×240 pixels one at a time would take ~1.4 s per frame; chunking in 128-pixel bursts reduces full-screen redraw to ~180 ms — fast enough for a usable UI at 4 fps.

Michael Rivas — Reflection

Coordinating a five-file Python agent with a three-device hardware chain revealed a consistent pattern: the hardest bugs were always at integration boundaries, not inside individual modules. Mocking external dependencies (Ollama, UART, FAISS) early enabled each module to reach a stable, testable state before integration, dramatically reducing late-stage debugging time.

8. Future Improvements

  • Multi-agent collaboration — add a Critic agent that reviews the Coder agent's output and a Tester agent that auto-runs generated tests, implementing Option 3 (Multi-Agent Collaborative System).
  • Vector database expansion — pre-index Python standard library docs, NumPy, and Pandas API references into the FAISS store for richer offline retrieval.
  • Quantised model — replace codellama:13b with codellama:7b-q4_K_M to halve memory usage and reduce latency to < 8 s on the Pi 5.
  • OTA firmware update — deliver Pico 2 .uf2 files from the Zero 2 W over USB-serial, eliminating the need for manual reflashing in the field.
  • True PPO reward — replace the EMA heuristic with a small PPO agent trained on a replay buffer of (prompt, output, rating) triples, enabling genuine policy gradient improvement.
  • Web dashboard — expose a lightweight React SPA from the Pi 5 so a laptop or tablet on the same Wi-Fi network can send queries and view sensor history without installing any software.
